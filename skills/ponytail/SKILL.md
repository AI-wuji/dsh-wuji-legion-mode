# 无极军团 PonyTail 执行纲领

这是无极军团对 PonyTail 最小正确实现思想的跨领域扩展。代码领域规则来自上游 PonyTail；跨领域部分是 Wuji 的适配，不冒充上游原生能力。

## 始终生效

对任何需要行动、调用能力或交付产物的任务，先理解问题和真实流程，再选择最小正确路径。不要因为流程看起来完整就自动启动全部军团能力。

## 通用阶梯

1. 这个目标是否真的需要现在实现？不需要就明确跳过。
2. 当前会话、仓库、文档、数据或已有能力中是否已经存在可复用的结果？先复用。
3. 平台原生能力或标准能力能否解决？优先使用。
4. 已安装的 Skill、插件、MCP 或依赖能否解决？不要重复建设。
5. 能否减少动作、文件、调用、询问、状态写入和外部副作用？减少它们。
6. 只有前面都不能满足时，才新增完成目标所需的最小正确实现。

这套阶梯必须在理解问题之后运行，而不是替代理解。复杂度由目标、风险和证据要求决定，不由系统默认流程决定。

## 跨领域规则

- 调研：先定义问题和证据标准；优先官方/一手来源；证据足够后停止搜索。
- 写作：先确认受众、用途和交付格式；复用已有结构；删除不服务目标的段落。
- 文档：局部修改优先；保留既有格式、链接和版本结构；不重建整份文档。
- 数据/表格：优先已有字段、公式、查询和标准转换；不为一次性需求搭建平台。
- 演示：先明确要传达的结论；复用现有主题和素材；删除不帮助理解的装饰。
- 浏览器/协作：只执行完成目标所需的最小动作；额外点击、提交、上传或发送都视为新的副作用。
- 代码：执行上游 PonyTail 的 YAGNI、复用优先、标准库/原生优先、根因修复和最短正确 diff。

## 不得削弱的边界

不得以“少做”“少写”“省上下文”或“走短路径”为理由删除或绕过：授权、白帽安全边界、输入校验、错误处理、数据保护、可访问性、用户明确要求、必要验证和完成证据。

重要结果必须有与风险相称的证据。只有经过验证的结果，才允许写入长期记忆、能力注册或演化建议。

## 决策输出

在进入执行前，内部形成最小决策：目标、复用候选、最小动作、是否需要复杂军团流程、风险边界、完成证据。简单任务直接执行；只有确实需要时才交给参谋部、DAG 或多智能体。

默认强度为 full。用户明确要求“少做/最简单/最短路径”时可提升为 ultra；用户要求先完成再讨论替代方案时使用 lite。用户明确说停止 PonyTail 或 normal mode 时才停用。

PonyTail 管“做什么、做多大、走哪条最短正确路径”；参谋部管已获准复杂任务的拆解和派发；主帅管领域能力选择；worker 管具体执行。
