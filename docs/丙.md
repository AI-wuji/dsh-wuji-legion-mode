## 二、命名规范要点

### 1. 分隔符：统一 `snake_case`，全部小写

**官方实证**：`@deepseek-ai/dsh-tool-*` 全部 22 个 `lib/index.js` 中，`name:` 字段共提取到 **28 个工具名，无一例外全部是 `[a-z][a-z0-9_]*` 的 snake_case**，未出现驼峰（camelCase）、连字符（kebab-case）或大写。

这条规范在官方文档中被**明确写出**（这是本次调研找到的最直接文字依据）：

- `dsh-tool-web/README.zh.md`：
  > 「**消费方拥有面向模型的约定。** 工具名称、schema、**snake_case 参数名称**、提示词区段、结果上限、格式化与呈现都定义在这里」

- `dsh-tool-fs/README.zh.md`：
  > 「字段名使用 snake_case，与 Claude Code 和现有 harness 工具 schema 一致。」

- `dsh-tool-fs/README.md`（英文原文）：
  > "Field names are snake_case to match Claude Code and existing harness tool schemas."

注：这两条原文的直接主语是**参数字段名**（argument/field names），工具名本身未被逐字规定为 snake_case。工具名遵循 snake_case 属于**从全部 28 个实例归纳出的强经验规律**（28/28 命中，无例外），而非文档明文条款。这一点在第四部分"推断"中标注。

### 2. 词序：`动词` 或 `动词_名词`，动作在前

- 单词动词：`read`、`write`、`edit`、`glob`、`grep`、`present`、`skill`、`bash`、`pwsh`、`ralph`、`ask_user_question`
- 动词_宾语：`todo_write`、`web_search`、`web_fetch`、`create_goal`、`get_goal`、`update_goal`、`read_image`、`send_message`、`interrupt_agent`、`str_replace_editor`、`cordis_inspect_list`、`cordis_inspect_query`、`load_workspace_dependencies`、`list_subagent_models`

未观察到任何"名词在前、动词在后"或"宾语_动词"的官方工具名。

### 3. 前缀分组：仅 4 个官方前缀族，且用下划线连接

从 28 个官方工具名中可归纳出 4 个前缀分组：

| 前缀 | 工具名 | 证据文件 |
|---|---|---|
| `todo_` | `todo_write` | `/dsh/node_modules/@deepseek-ai/dsh-tool-todo/lib/index.js` |
| `web_` | `web_search`、`web_fetch` | `/dsh/node_modules/@deepseek-ai/dsh-tool-web/lib/index.js` |
| `job_` | `job_output`、`job_list`、`job_kill` | `/dsh/node_modules/@deepseek-ai/dsh-tool-jobs/lib/index.js` |
| `cordis_` | `cordis_inspect_list`、`cordis_inspect_query` | `/dsh/node_modules/@deepseek-ai/dsh-tool-cordis/lib/index.js` |

另有 `goal` 域工具（`create_goal`/`get_goal`/`update_goal`，同一包 `dsh-tool-goal`）——采用**动词前缀**而非 `goal_` 名词前缀，说明官方**不做强制的前缀归组**：同域工具既可共享名词前缀，也可共享名词词干配不同动词。

**关键观察**：官方前缀分组是**按功能域**（todo / web / job / cordis），而**不是按归属方或来源**（没有任何 `dsh_*` 前缀的工具名）。工具所属的包名（`dsh-tool-web`）与工具名（`web_search`）之间是"包名以连字符 kebab-case、工具名以下划线 snake_case"的**两套独立命名空间**。

### 4. 单复数与缩写

- 单复数**由语义决定**，无统一规则：`cordis_inspect_list` 用单数 `list`（指"这份列表"），`job_list` 同样单数；`load_workspace_dependencies` 用复数（确实加载多个依赖）。
- 缩写**几乎不用**：未观察到 `msg`、`cfg`、`req`、`exec` 之类的模型可见缩写。反例仅有 `pwsh`（PowerShell 的官方既定缩写）和 `str_replace_editor` 中的 `str`。
- `subagent` 写作**一个词**（不拆成 `sub_agent`），出现在 `subagent_fork`、`subagent-control` 等位置。

### 5. 包名 vs 工具名的双层规范

| 层 | 规范 | 实证 |
|---|---|---|
| npm 包名 | `@deepseek-ai/dsh-` + **kebab-case** | `dsh-tool-web`、`dsh-tool-fs-search`、`dsh-tool-call-timeout-policy`、`dsh-experimental-tool-agent-team` |
| 工具名 | **snake_case** | `web_search`、`glob`、`job_output` |

**注意**：包名中 `tool` 是**单数**（`dsh-tool-*`），且部分是**复合职能包**而非单一工具包，例如：
- `dsh-tool-fs` 一个包注册 4 个工具：`read`、`write`、`edit`、`read_image`
- `dsh-tool-fs-search` 一个包注册 2 个工具：`glob`、`grep`
- `dsh-tool-jobs` 一个包注册 3 个工具：`job_output`、`job_list`、`job_kill`
- `dsh-tool-pwsh-persistent` 注册 `pwsh`，`dsh-tool-bash-persistent` 注册 `bash`

即：**包与工具不是一一对应**，包名是**能力域**，工具名是该域下一个具体动作。

## 四、反例与偏离：自研 `wuji_staff_*` 的核实结果

### 4.1 事实核实

**被质疑的说法**：`wuji_staff_plan` / `wuji_staff_select` 的正则描述里声称「provider, and method must come from cordis_inspect_list」。

**核实结果（分两部分，必须分开说）**：

**第一部分：命名格式本身。** 实际源码实证：

- 工作区当前插件 `E:\wuji-projects\dsh-wuji-legion-mode\packages\wuji-staff\lib\index.js`
  - 第 83–84 行：`ctx.tools.register(defineTool({` / `name: 'wuji_staff_plan',`
  - 第 146 行：`name: 'wuji_staff_select',`

- 历史备份版本 `C:\Users\Administrator\.dsh\backups\stale-agent-presets-20261008-161057\node_modules\@wuji\dsh-wuji-host\lib\staff.js` 中还有一批同族工具：
  - 第 20 行 `name: 'wuji_staff_plan'`
  - 第 96 行 `name: 'wuji_staff_dispatch'`
  - 第 138 行 `name: 'wuji_task_complete'`

同备份包内其他 `wuji_` 工具（`laya-router.js:62` `wuji_route`、`laya-router.js:118` `wuji_contract`、`officers.js:5` `wuji_officer_advise`、`officers.js:19` `wuji_council_plan`、`commanders.js:8` `wuji_commander_select`、`intelligence.js:4` `wuji_intelligence_search`、`observability.js:12` `wuji_feedback_record`、`observability.js:13` `wuji_status`、`evolution.js:13` `wuji_memory_write`、`evolution.js:14` `wuji_evolution_propose`、`evolution.js:15` `wuji_evolution_promote`）。

**命名格式结论**：`wuji_staff_plan` / `wuji_staff_select` 采用 `snake_case`，**与官方分隔符规范一致，不构成格式偏离**。

**第二部分："must come from cordis_inspect_list" 这句声称本身。** 我**没有在工作区的 `packages\wuji-staff\lib\index.js` 中找到这句英文原文**——用 grep 检索 `wuji_staff_plan` / `wuji_staff_select`，仅在 `index.js:84`、`index.js:96` 命中，第 96 行只是中文描述「已知无可用承接方的子任务 id（来自 wuji_staff_select 的缺口）」。**因此该英文声称是否存在于 `wuji_staff_select` 的描述文本中，本次未能正面证实**（我只读了 78–107 行窗口，未通读全文；可能是上下文或正则描述用词，也可能该说法本身不准确）。**此处标注为未查证，不下断言。**

**关于前缀分组的偏离（有实证）**：官方 28 个工具名中**没有任何按"归属方/厂商"分组的前缀**——前缀只有 `todo_`/`web_`/`job_`/`cordis_`，全部是**功能域**。`wuji_` 是**项目/军团品牌前缀**，这一分组维度**在官方命名中不存在**。

### 4.2 偏离评估

| 维度 | 官方 | `wuji_*` | 是否偏离 |
|---|---|---|---|
| 分隔符 snake_case | ✅ | ✅ | **不偏离** |
| 全小写 | ✅ | ✅ | **不偏离** |
| 动词/名词词序 | 动词在前（`todo_write`、`job_output`） | `wuji_staff_plan`（品牌_名词_动词）、`wuji_staff_select` | **顺序不冲突但多一层前缀** |
| 前缀维度 | 仅功能域 | 品牌 `wuji_` | **偏离** |
| 层级深度 | 最多 3 段（`cordis_inspect_list`） | 最多 3 段（`wuji_staff_plan`） | 不偏离 |

**结论**：`wuji_staff_*` 在**字符格式层面完全合规**，偏离点在**前缀语义**——官方只用功能域前缀，自研引入了品牌前缀。这是**有意的扩展命名空间**，属设计选择，不算格式违规，但确实与官方风格不同。

**关于 `wuji_staff_plan` 与 `cordis_inspect_list` 的"差异"**：任务背景暗示两者存在差异需核实。实测得出的差异是：

- 两者**格式相同**（都是 snake_case 三段式）
- 两者**归属层不同**：`cordis_*` 是**官方功能域前缀**（cordis 是 DSH 的组合框架名，本身就是系统组件），`wuji_*` 是**第三方品牌前缀**
- 因此"偏离官方风格"的说法**在格式上不成立，在语义分组上成立**

## 五、结论与建议

### 5.1 结论

1. **分隔符**：官方工具名 28/28 全部为 **snake_case 全小写**，零例外。文档层面对**参数字段名**明文要求 snake_case（`dsh-tool-web/README.zh.md`、`dsh-tool-fs/README.zh.md`）。
2. **词序**：官方一律**动词在前**；`动词_名词` 或单个动词，无"宾语_动词"形式。
3. **前缀**：官方仅 4 个功能域前缀（`todo_`/`web_`/`job_`/`cordis_`），**无厂商/品牌前缀**。
4. **层级**：官方工具名最多 3 段（`cordis_inspect_list`），通常 1–2 段。
5. **包名与工具名分层**：包名 kebab-case（`dsh-tool-web`），工具名 snake_case（`web_search`）；一个包可注册多个工具，包名指代**能力域**而非单个工具。
6. **`wuji_staff_plan` / `wuji_staff_select`**：格式合规，前缀分组偏离官方风格（品牌前缀 vs 功能域前缀）。

### 5.2 建议

1. **不要为了"对齐官方"而重命名 `wuji_staff_*`。** 格式已合规；品牌前缀是**功能性隔离手段**，能让使用者一眼区分自研扩展与官方工具，在混合工具列表中反而降低混淆。重命名只会破坏已发布工具名，违反"不改没问题的内容"。**（本建议属价值判断，非实证结论。）**
2. **新工具命名应遵守三条硬约束**（有实证支撑）：全小写 snake_case；动词在前；不超过 3 段。
3. **若要新建工具，谨慎评估是否真的需要。** 官方已提供 `todo_write`、`subagent`、`workflow`、`goal`、`ralph`、`job_*` 等完整编排能力，自研工具应证明官方能力无法满足再新增。
4. **参数名必须 snake_case**（这是**文档明文要求**，非归纳）：`dsh-tool-fs/README.zh.md` 与 `dsh-tool-web/README.zh.md` 均已明示。注意 `wuji_staff_plan` 现在的参数 `gap_ids`、`parallel_cap` 已符合此规范。

### 5.3 明确标注的推断项（无确凿依据）

| 论断 | 依据状态 |
|---|---|
| 「工具名必须 snake_case」是**官方明文规范** | **未找到依据。** 找到的是针对**参数字段名**的 snake_case 明文要求；工具名的 snake_case 是**从 28/28 实例归纳的强规律**，属推断 |
| 官方存在统一的"工具命名约定"文档 | **未找到依据，属于推断。** `dsh-tool-fs/README.zh.md` 引用了 `../../../docs/tool-catalog.md`，但该文件**未被打包进 app.asar**（已全量枚举确认，`tool-catalog` 零命中），无法读取其内容 |
| 工具名是否有正则/长度校验 | **未查证。** 未在 `dsh-tools/lib/index.js` 定位到名称格式校验逻辑（仅读了该文件前 3000 字符） |
| `subagent`、`subagent_fork`、`exit_plan_mode` 的注册名与来源 | **未查证。** 未在上述 28 个字面量中命中，可能为动态构造 |

## 六、复现方法

本报告所有 asar 内部证据可用以下方式复现（Node.js 读取 asar 头）：

```js
const fs = require('fs');
const p = String.raw`C:\Users\Administrator\AppData\Local\Programs\DeepSeek Harness\resources\app.asar`;
const fd = fs.openSync(p, 'r');
const b = Buffer.alloc(16); fs.readSync(fd, b, 0, 16, 0);
const hs = b.readUInt32LE(12);                 // header size
const hb = Buffer.alloc(hs); fs.readSync(fd, hb, 0, hs, 16);
const tree = JSON.parse(hb.toString('utf8').replace(/\0+$/, ''));
const BASE = 16 + hs;                          // 文件内容起始偏移
// 每个节点: { offset, size }，绝对位置 = BASE + offset
```

用该方式可枚举全部 12,967 个文件，并读取任意 `@deepseek-ai/dsh-tool-*/lib/index.js` 的原文。

**未修改 `app.asar` 或 `app.asar.unpacked` 内任何文件；本次唯一写入的文件是本报告。**
