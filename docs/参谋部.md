# 参谋部（@wuji/dsh-wuji-staff）

无极军团 4.0 在 DSH 上的**执行图谱写入者**。

## 为什么有这个东西

3.0 蓝图定了两条核心权责：

```
阿极   = 需求图谱的唯一正式写入者   → 理解用户要什么
参谋部 = 执行图谱的唯一正式写入者   → 决定怎么干、派给谁、何时并发
```

这两者**不能合并**。蓝图第 2 节专门解释了原因：阿极优化的是沟通速度与需求保真，
参谋部优化的是任务拆解、依赖关系、调度决策与验收闭环 —— 一个角色同时做两件事，
两边都会做差。

## 为什么是插件，不是 workflow 脚本

`workflow` 脚本每次都要由模型**现场生成**：

- 烧 token（每次都要重新产出整段脚本）
- 有延迟（生成本身要时间）
- **不可复现**（每次产出可能有细微差异，同一个输入未必得到同一个计划）

而参谋部的调度逻辑是**确定性**的 —— 同样的输入永远该得到同样的计划。
所以它应当**一次性写定**，随 preset 自动挂载：

- 用户无需手动选择（选中「无极军团」即自动加载）
- 模型无需生成（直接调用工具）
- 结果可复现、可审计

## 与官方的边界（诚实说明）

已核实官方 289 个包中**没有**调度器。这是本仓库唯一有意保留的自研运行时，
并在 `scripts/check-wuji-preset.mjs` 的 `ALLOWED_SELF_BUILT` 白名单里登记 ——
任何白名单外的 `@wuji/*` 行都会让校验失败，防止自研面重新蔓延。

## 职责边界：只做确定性部分

依据 3.0 蓝图 L110：

> 参谋本部主要做**调度和判断**，困难的架构、推理或审查任务应派给 Sol 子代理，
> **不要求参谋本部亲自完成所有高难度工作**。

因此本插件**只**承担确定性的部分：

| 职责 | 性质 | 本插件是否承担 |
|---|---|---|
| 领域/意图打分选择 | 确定性（3 分 + 2 分/意图） | ✅ |
| 依赖图、并发分组、写集冲突 | 确定性 | ✅ |
| `selection_gap` 判定与传播 | 确定性 | ✅ |
| **最小上下文投影** | **语义提炼** | ❌ 交给模型 |
| **产物是否达标** | **判断** | ❌ 交给模型 |

后两项属于语义判断。3.0 蓝图的 L105「为每个子代理生成最小上下文投影」需要读懂
任务语义才能提炼，本插件不假装能做 —— 那是模型该干的。

## 工具

### `wuji_staff_plan`

把阿极的需求表转成执行计划（任务分配表）。

输入：子任务列表（`subtask_id` / `goal` / `domain` / `typed_intents` /
`depends_on` / `write_roots`），可选 `gap_ids` 与 `parallel_cap`。

输出：并发分组、被阻塞分支、写集冲突说明。

语义要点：

- 依赖未满足的子任务不进入本组
- 写集冲突（**含目录包含关系**）的子任务不在同一并发组
- `selection_gap` 阻塞该分支，且**沿依赖传播**给后继
- 被阻塞的分支**不影响**无依赖的其他分支
- 依赖成环 / 重复 id / 缺必填字段时明确报错，而非静默产出错误计划
- 输出带 `construction_only: true` —— 这是计划，不冒充已发生的执行

### `wuji_staff_select`

为一个子任务选择承接的主帅/专家团。

按上游权重打分：领域命中 3 分，每个命中的类型意图 2 分。
**无匹配或最高分并列都算 `selection_gap`** —— 禁止查全能力兜底，也禁止临时编造主帅。

node packages/wuji-staff/staff-core.test.js   # 25 项

写集冲突串行、依赖有序、缺口不拖累其他分支），这里固化成回归测试。
