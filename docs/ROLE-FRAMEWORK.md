## 二、官方模板原文（W5 §2.1，逐字）

```
# 角色
你是 {一个什么身份 / 有什么专长的专家}。

# 任务
你的职责是 {一句话说清要帮我完成什么}。

# 流程
按下面步骤执行：
1. {第一步做什么}
2. {第二步做什么}
3. {第三步做什么}

# 约束
- {必须遵守的规则}
- {绝对不能做的事}

# 输出
最终用 {什么格式} 输出，包含 {哪几块}。
```

第 106 行称此结构为「**五要素齐全，输出稳定**」——与 `catalog/p3/experts.json` 里的
`five_elements`（goal / inputs / process / output / acceptance）**命名一致**。

第 220 行给出更完整版：`角色定位、工作流程、输出规范、约束边界、所用 Skill`。

**WorkBuddy 专家团的 12 份文件即照此模板产出**，故骨架天然统一
（见 `docs/WORKBUDDY-INTEGRATION.md`）。

## 五、诚实边界（不得省略）

上游 `catalog/p3/experts.json` 中，**字段的真实性并不一致**：

| 字段 | 取值数（共 57 条） | 性质 |
|---|---|---|
| `goal` / `inputs` / `output` / `acceptance` | **57 种** | ✅ 真实、差异化 |
| `anti_trigger` | **57 种** | ✅ 真实、差异化 |
| `process` | **1 种** | ❌ **占位符**：全部为「按 workflow-contracts 当前领域流程…」 |
| `scope_rule` | **1 种** | ⚠️ 全局通用契约 |
| `cancellation` | **1 种** | ⚠️ 全局通用契约 |
| `delegation-manifest.json` 的 `assignment` | **4/85 条** | ⚠️ 非通用字段，缺失时回退到该专家 `goal` |

**因此：**

1. **「工作流程」一节没有源数据可抄**，是按框架 + `goal`/`acceptance`/`anti_trigger` 推导补写的，
   属**通用结构**，**不是该领域的专业操作序列**。专业步骤须由真实执行经验补充。
2. `scope_rule` / `cancellation` 是**全局约定**，文件中已标注为「通用契约」，**不伪装成该专家独有**。
3. `## 所用 Skill` 是 **DSH 集成层内容**，上游 `experts.json` 中不含
   `wuji_staff_plan` / `subagent` 等概念（命中 0 次），已在各文件内明确标注。
4. `domains` / `typed_intents` 来自 `delegation-manifest.json` 的配方定义（各 21 条），
   **不在** `experts.json` 中。
5. 上游对 `catalog/p3` 的整体标注是「**契约已写、专业效果未验证**」。
   这批文件证明的是**职责已定义且可被选择**，**不证明该职责已被独立验收**。

**未做的事**：没有为 57 个专家编造领域专业知识。框架填的是源数据里真实存在的差异化字段；
缺失的部分如实标注为补写，而不是用看起来专业的措辞掩盖。

## 六、生成器与校验

- `scripts/build-wuji-roles.mjs` — 生成 frontmatter **并**渲染框架正文（顺序：先写文件，再渲染）
- `scripts/rewrite-roles-framework.mjs` — 框架渲染器（单一来源）
  - `--apply` 写入（build 调用）／`--check` 只报告差异／`--stats` 统计
- `scripts/verify-wuji-roles.mjs` — 断言新框架的六个必填章节 + 主帅成员数 + 配方归属

### 一次真实失败（留档）

早先框架渲染是**独立一遍**（build 生成 → rewrite 重写），而 `verify-all.mjs` 会跑
`build-wuji-roles.mjs` 重新生成 —— 于是重写内容被**覆盖回旧结构**，且一度被误判为
「重写失败」。真实的根因是**顺序**：渲染必须在文件写入**之后**。
现已合并进生成流程，`--check` 同时校验 frontmatter 与正文，不会再分叉。
