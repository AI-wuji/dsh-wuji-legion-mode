# Harness 端点与上下文诊断

## 结论

1. DSH GPT provider 当前配置为 `openai-completions`，因此请求走 `/v1/chat/completions`。
2. Codex 使用 `/v1/responses`，两者不是同一 wire protocol；模型命中、工具格式、图片和缓存行为不能仅按模型名比较。
3. DSH `dsh-llm-pi-ai` 同时支持 `openai-completions` 与 `openai-responses`，但当前 Hubway 是否完整兼容 Responses 需要真实 provider 健康测试，不能直接切换。
4. 图片能力由 `input: [text,image]` 和 `llm.resolveModelInfo()` 控制；当前 GPT 模型已声明图片。
5. 上下文 648.8K 是完整请求 surface，不等于聊天文本：包含 system prompt、工具 Schema、Skill/运行时上下文、历史消息和投影。需要用 tokenMeter 分项测量，不能凭截图单点归因。

## 发现的配置事实

> 2026-09-30 实测：本机 DSH profile 实际配置的 provider 为
> `spacebunnyalpha`（openrouter）、`qwen38`（127.0.0.1:8081）、
> `local-bonsai`（127.0.0.1:18080）。默认模型由
> `@deepseek-ai/dsh-agent-default-model` 指定。
>
> 3.0 起军团**不再记录具体模型名**——模型是宿主配置，军团继承之。
> 详见 [`docs/模型路由.md`](模型路由.md)。

- 模型 provider / model 均由宿主 profile 配置决定，军团继承当前模型
- DSH LLM 适配器代码支持 `openai-responses`
- DSH 客户端在模型 `inputModalities` 不含 image 时，会明确拒绝带图片的模型切换
- DSH 有 `tokenMeter.measure(session, requestHeader)`，可测量当前请求压力和 surface

## 已确认的外部解决方案

| 方案 | 来源 | 纳入无极军团的方式 |
|---|---|---|
| 稳定前缀 + 变化后缀 | OpenAI Prompt Caching / Anthropic Prompt Caching 官方文档 | 固定铁律/角色框架/工具骨架放前；当前任务和投影放后 |
| 渐进披露 | Anthropic Skills（170K+ stars） | 目录只提供名称/说明/边界，命中后才加载 SKILL.md 和 references |
| 简单可组合 agent | Anthropic Building Effective Agents | 不增加第二套 harness、记忆或 supervisor |
| 执行前 Guardrails | OpenAI Agents SDK 官方 | 在工具 Schema/执行前门禁解决，避免生成后循环重做 |
| 模型/任务路由 | vLLM Semantic Router | 同厂家内按任务能力和模型实际 metadata 路由 |
| 统一能力治理 | HarnessKit | 只借鉴 Skill/MCP/Plugin 来源、权限、版本和回滚目录，不安装为核心依赖 |

## 建议的最小修复顺序（尚未执行）

1. 先对宿主当前模型在 `/v1/chat/completions` 和 `/v1/responses` 做只读/低风险健康测试，比较：HTTP 成功、工具调用、reasoning、图片、延迟、token。
2. **不跨厂家切换已废弃**：3.0 起军团继承宿主模型，只在同模型内切 reasoning effort（见 `docs/模型路由.md`）。跨 provider 决策属于阿极，不由路由层自动完成。
3. 用 tokenMeter 对当前会话测量后，再减少工具/Skill/历史注入；不直接删除历史。
4. 对阿极使用轻量 preset 和稀疏上下文；参谋部/执行层按任务档位单独路由。
5. 只有健康测试证明 Responses 兼容且收益明确，才把对应 provider 切到 `openai-responses`。

> 2026-09-30 实测更正。本节此前声称「默认 preset 已从 `cordis` 改为 `wuji`」，
> 该说法**与实际不符**，且与 `docs/实现状态.md`、`docs/MODE-IMPLEMENTATION.md`
