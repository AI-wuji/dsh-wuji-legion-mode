# 主帅/领域路由摘要

本文件是 4.0 入口的路由摘要，**不是**专家正文，也不代表任何专家已经启动。

## 固定通路

简单任务由阿极直办。复杂任务按交付需要拆成一个或多个明确子任务：

```
阿极（任务契约、按需拆分）
  → 领域选择（本文件）
  → 子任务委派（subagent / workflow）
  → 必要窄专业指引（skill 按需加载）
  → 结果汇总
  → 独立复核（需要时）
  → 阿极统一交付
```

## 领域路由表

原 4.0 的 16 主帅族 / 21 条配方，在 DSH 上收敛为**按领域选择现有 skill + 原生工具**：

| 领域 | 承接方式 | 典型意图 |
|---|---|---|
| 治理 / 元指令 | `ponytail-audit` + 人工 review | 规则修订、来源审计、准入判断 |
| 研究 / 选型 | `ponytail-research` + `web_search` / `web_fetch` | 技术选型、根因、兼容性、外部事实 |
| 软件实现 | `ponytail-code` + `subagent` | 编码、重构、架构、语言选择 |
| Bug 修复 | `ponytail-code` + `ponytail-review` | 复现、根因、回归修复 |
| 代码审查 | `ponytail-review` + 独立 `subagent` | 独立审查，作者不冒充审查者 |
| 办公文档 | `office-docx` / `office-xlsx` / `office-pptx` | Word、Excel、PPT、PDF |
| 演示 | `dashi-ppt` | 汇报材料、幻灯片 |
| 写作 | `ponytail-writing` | 文章、文案、剧本、翻译 |
| 前端 / 网页 | `ponytail-code` + `ponytail-browser` | 网站、界面、可视化检查 |

## 选择与回交口径

- 由阿极完成结构化拆分，不要求用户写 JSON 或点名专家。
- 每个子任务独立选择承接能力：领域匹配优先，其次看是否有现成 skill。
- 无精确匹配或多个并列时，只阻塞该子任务及其后继，其他分支继续；**禁止全能力兜底或临时编造专家**。
- 委派给子 agent 时必须带上：目标、输入、产物位置、验收、禁止动作、写范围、依赖结果。
- 子 agent 回交实际产物位置、执行与检查结果、未做和阻塞；阿极汇总后统一交付。
- **`prepared` / `已派发` 只表示准备或已创建，不表示已启动、已运行或已完成**；执行、工具权限和专业效果必须另有真实证据。

## 从选择到实际执行（DSH 原生）

- 简单任务仍由阿极直接完成；复杂任务选定能力后，把准备数据接到真实工具动作，**不停在能力名单**。
- 单任务用 `subagent`；需要继承当前上下文用 `subagent_fork`。
- 多分支独立任务用 `workflow` 脚本；有依赖的用 `pipeline`，需要汇聚的用 `parallel`。
- 需要跨回合持续推进用 `goal`；需要自动连续多轮用 `ralph`。
- 长产出用 `present` 登记为交付物。
- 检查只针对本次实际风险，独立审查不能由作者冒充；没有必要不加步骤表、评审人数或镜像式文本测试。
