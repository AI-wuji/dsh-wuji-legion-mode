# 改造说明 · 立体文化长卷九风格元指令

改造人：苏墨（image-prompt-architect）／图像域
产出：《九风格长卷元指令.md》
结论先行：原稿的**视觉设计内核是可用的**，但它的**格式层（模型归属、输出形态、惩罚式约束堆叠、条数预算）不可执行**，且**存在两处逻辑错误**（水墨段与单轴头句冲突、无生命化规则扩展到了人物）。改造采取"保留设计内核 + 重写格式层 + 补长度预算"的策略。

---

## 一、格式归属判定

### 结论

**原稿未声明目标模型，本身无法判定它原本是为哪个模型写的。** 这一点我明确说：**无法判断原稿的目标模型**——缺的前提是"作者当时打算投给哪个编码器"，这个信息在原稿里不存在，任何判定都是替作者假设。

**但改造必须锁定一个目标模型才能落地**（本域规则：目标模型语法锁定优先于用户参考格式）。我的处理是：**显式声明这是一个设计决策，不是对原稿事实的认定**，文件头写 `[model: GPT image, version: 2.5]`，并在文件头标注"前提……依据见《改造说明.md》"，不把它伪装成原稿既有事实。

### 为什么选 GPT image 2.5（而非 qwen-image 2.1）

1. **输出形态要求是 prose，不是维度字段。** 原稿要求"自然语言句式，避免机械罗列"、"每条为一个完整段落"。这与 GPT image 2.5 的"生产简报式散文 + 官方八原则"`[官方]` 天然同构；qwen-image 2.1 分支更偏"结构化维度写法（主体/构图/视觉风格/材质与光线/输出意图/约束）"。→ **推断（结构性论证），非官方断言**
2. **原稿通篇是"先排除、后描述"的否定式指令堆叠**（"明确禁止……"、"不得……"）。2.5 **没有独立 negative 字段**`[官方]`，负面表达只能写成可见的行为约束——这正是原稿需要被重写的部分，也就是说选 2.5 会让这个缺陷暴露并被正面处理。若选 qwen 分支，负向有效性还取决于 `true_cfg_scale > 1`（CFG 默认 1 时负向无效）`[官方]`，而原稿完全没有控制这个参数，判定链条会更长。
3. **九宫格口径一致性要求高**（9 段同风格体系、元素必须同材质）。2.5 的"每轮重述关键保持项"`[官方]` 与之匹配。

> ⚠️ **一项无法判断**：原稿的 9 段是"一次调用生成 9 段文本"，实际出图时是**9 次独立生成**。GPT image 2.5 是否能在 9 次独立生成间保持同一套"卷轴 + 文化主题"世界观，**我没有该模型的实测证据，无法判断**，缺的前提是 9 次生成间的风格漂移实测数据。这一点原稿也没有处理，属于遗留风险，不是本次改造能消解的。

### 被拒绝的格式参考

原稿中**没有出现任何其他图像模型的语法特征**（无 SDXL/Pony/booru 逗号标签、无 JSON 字段契约、无 Midjourney 的 `--ar` / `--style` 参数、无 LoRA/VAE 引用）。因此**没有被拒绝的外部格式**，也不存在"标签类模型提示不支持"的触发条件。→ **实测（对原稿全文 grep 结论）**

## 三、最关键的三个发现

### 1. 格式层不可执行：原稿没有模型归属，也没有长度预算

无模型声明 → 无法判定原始目标；无长度预算 + 9 段各含大量强制短语 → 篇幅失控，且**重复短语不产生额外约束力**（这正是"长度不是越长越好"要防的）。改法：锁定 2.5（决策，已标注前提）+ 150–220 词/段 + 回指句省写。

### 2. 剔除短语不是全冗余 —— 不可一刀切删除（这一条我修正了自己的初判）

我最初的判断是"重复的剔除短语属无效膨胀，应当大幅删减"。**这个判断下得太快。** 原稿自己在收尾处记录了前科："此版本已彻底封堵'水墨风出现狼头''写实瓶贯穿所有风格'等漏洞"——说明该设计**在实测中确实发生过风格串味**。

因此正确的处理不是删除，而是：
- **合并重复项**（三条同义剔除 → 一条）；
- **把剔除锚定到已发生的失败模式**（水墨段保留 "no cartoon lines, no clean vector outlines"），而不是全域无差别加负向；
- **明确"一条针对性剔除"优于"十条通用剔除"**。

### 3. 无生命化规则被过度扩展，与三个风格直接冲突

原稿收尾句要求每段都出现 `no living creatures, no faces, no eyes, no limbs`，但同一份原稿又要求：
- 第 5 段"所有人物必须为 1 厘米左右高的毛绒小人偶"；
- 第 6 段"人物皮肤细节"；
- 第 7 段"微型人偶……姿态自然，动作多样（行走、交谈、战斗、航行、读书）"。

**同一 prompt 内正面要求"人物要有动作神态"、负向要求"不要脸和肢体"，模型必然随机取舍**——这是原稿最严重的自相矛盾，比轴头问题影响面更大（波及 3/9 段）。作者原意只约束**非自然元素**（毛笔、光效、容器），第 11 项改动已加显式边界消歧。

## 四、合规判断

### 4.1 判定：原稿在处理"路飞"这类受版权保护的具体角色时，**不成立**，存在真实风险

**依据链**（区分事实与推断）：

- **事实（原稿内部证据）**：原稿在同一份文档里给出了两条互相拆台的规则——
  - §一：对强现实关联元素"严禁直接复刻现实物体形态、**品牌标识**或摄影细节"；
  - §四：写实风格"是**唯一允许接近现实形态**的风格"。
  两条叠加的净效果是：**写实风格下接近现实形态是被允许的**。而原稿又把"路飞/草帽"直接写进输入示例和转译清单。
- **推断（法律层面，明确标注为我的推断，非法律意见）**：角色形象著作权与商标权属于**知识产权法**管辖，与"品牌标识 / 商业符号"不是同一概念。原稿的合规语句只覆盖了品牌与商业符号，**没有覆盖受版权保护的角色形象**。因此"转译为材质化符号即不构成复刻"这个辩护**在文本层可以自洽，但不构成合规背书**——一份免责短语不会改变生成物与原作的实质性相似风险。
- **诚实结论**：我能判断的是"**原稿的写法与它自己声明的合规要求不一致，且覆盖范围不足以处理版权角色**"；我不能判断的是"该生成物在特定法域下是否侵权"——**这需要法务判断，我无法判断，缺的前提是适用法域与具体发行/商用场景。**

### 4.2 我的处理（最小正确动作）

不是把角色名全部删光，而是**把风险点从"模型输入"移到"作者决策"**：

1. **元指令内不出现任何受版权保护的角色名与作品名**（路飞 / 海贼王 / 千阳号 / 林黛玉 / 孙悟空等）——避免模型把书名号内容当作必须再现的对象；
2. **输入示例改为类别化**（"角色 / 动漫作品"），保留"角色"这个类别本身，用户想用仍可以用；
3. 在 §1.5 增加一条明确硬规则：**受版权保护的角色只保留经材质化转译后的抽象符号，不出现可识别特征与可识别外观；可识别的脸、标志性服装剪影、作品标题文字一律不出现**；
4. **写实风格**的转译行单独写明："无标识的同类实物，不出现商标、包装、商业文字"——**堵死"唯一允许接近现实形态"这个例外被用来生成可识别商品/角色**的通道；
5. 地名对应的商业商品（青岛啤酒瓶）**降级处理**：不作为画面主角，改用当地建筑、山水、民俗物。

### 4.3 一处我不做判断的地方

"把商标图案转译成发光轮廓算不算商标使用"——**我无法判断**，缺的前提是具体法域、使用方式（个人欣赏 / 商用发行）与注册类别。元指令层面我只能做"不出现商标、包装、商业文字"这一条可执行的正面约束。

## 五、保留了什么 & 为什么

| 保留项 | 理由 |
|---|---|
| 9 风格顺序与序号 | 用户核心契约，顺序是元指令的硬结构 |
| 卷轴作为"唯一容器"的核心设定 | 设计内核，全篇以此成立 |
| 单一轴头 / 右端消失 / 悬浮无支撑 | 视觉识别的关键特征，且有真实踩坑记录支撑 |
| 水墨段用悬空毛笔替代轴头 | **这是可接受的风格例外，不是矛盾**（见下） |
| 9 风格的材质体系描述（金箔/纸雕/湿墨/晶体/毛毡/写实/树脂/霓虹/水彩） | 风格矩阵是这份元指令最有价值的部分，几乎逐字保留 |
| 9 风格的背景设定 | 同上 |
| 标志性符号的 9 风格转译表 | 设计意图正确（可见结果），只改动了举例方式 |
| "立体元素不少于 7 个" | 可执行的数量约束 |
| 空间叙事链、动线、比例协调 | 这是"避免罗列"的真实手段，保留并写得更具体 |
| 微观小人的按关键词分流（地名/影视/人物） | 逻辑正确且可执行 |
| "非自然元素无生命化" | 语义保留，仅加边界防误读 |

### 关于轴头"矛盾"的判定

**这不是真矛盾，是可接受的风格例外 —— 但例外没有被正确地表达在句子层，这才是真实缺陷。**

- **依据**：例外是**有条件的**（"若为水墨幻境风格"），作用域明确（只作用于第 3 段），且指向一个不同的实体（毛笔替轴头），不是同一实体的两种状态。同段落里下位规则覆盖上位通则，是正常的规则层级。
- **真正的缺陷**：原稿把"必须包含 the scroll has only one roller on the left"写成了**无条件的全域要求**。于是第 3 段同时被要求"取消轴头"和"必须包含单轴头句"——**这个句子在逻辑上就是假的**（该段没有轴头）。
- **修正**：把例外提升到句子层，给第 3 段一套专属句子（`the scroll has no roller at all…`），并在第 3 段明文**禁止**使用单轴头句。这样例外从"规则里的口头说明"变成"结构上的独立分支"，模型不会在两个互斥的"必须包含"之间随机取舍。

## 七、遗留风险（如实记录，未消解）
